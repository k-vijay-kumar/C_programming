# Storage Classes and Linkage

Storage-class specifiers affect properties such as storage duration and linkage. They do not, by themselves, determine a variable's physical memory location.

## `auto`

`auto` is the default storage-class specifier for block-scope objects. Such objects normally have automatic storage duration: their lifetime is limited to execution of the block. An uninitialized automatic object has an indeterminate value; reading it can cause undefined behavior.

## `register`

`register` requests that an automatic object be accessed quickly, but the compiler may ignore the request. It does not guarantee storage in a CPU register. The address-of operator cannot be applied to an object declared `register`.

## `static`

Objects with static storage duration exist for the entire program execution and are zero-initialized if no initializer is provided.

- A block-scope `static` object retains its value between function calls; its name remains visible only within its block.
- A file-scope `static` object has internal linkage, so it can be referred to only within that source file.

## `extern`

`extern` declares an object or function with linkage, commonly to refer to a definition in another source file. A declaration such as `extern int count;` usually does not define the object; a definition must exist in the program. File-scope objects have external linkage by default unless declared `static`, but not every global declaration is itself an `extern` declaration.

Scope (where a name is visible), linkage (whether declarations refer to the same entity), storage duration (how long an object exists), and initialization are related but distinct C concepts.
